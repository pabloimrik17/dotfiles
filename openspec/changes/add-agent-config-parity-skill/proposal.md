## Why

Agentic-tool config in this repo drifts. When a Claude Code setting, plugin, or command lands in `dot_claude/`, nothing prompts the equivalent question for OpenCode (`dot_config/opencode/`) or Junie, and no record says whether an equivalent even exists. The result is silent, undocumented divergence between three tools that do largely the same job.

The repo's own skills show the same drift at a second level: `update-manual`, `update-readme`, and `classify-tool-updates` are byte-duplicated across `.claude/skills/` and `.junie/skills/`, kept in sync by hand. User-scope skills already solved this — `gh skill install` and `skills.sh` put the body in `~/.agents/skills/<name>` and leave `~/.claude/skills/<name>` as a symlink (see `gh-skill-install`, `slidev-skill-install`). Repo-local skills never adopted it.

## What Changes

**New skill `sync-agent-config`** — proposes cross-tool replication of user-scope agentic config:

- Triggers on additions, modifications, and removals under the chezmoi-managed user-scope surfaces: `dot_claude/`, `dot_config/opencode/`, and the Junie user-scope surface once one exists.
- For each change, identifies the equivalent surface in the other two tools and **proposes** the matching edit. Never applies unattended — same gate as `classify-tool-updates`.
- When a feature has no equivalent in a tool, records that as an explicit gap rather than silently skipping it.
- Owns a parity table at `parity.md` inside the skill directory, **initialized empty** (headers only) and extended as mappings are discovered.
- Scope is user-scope config only. Project-level `.claude/`/`.opencode/`/`.junie/` config is out of scope.

**Canonical repo skill layout** — repo-owned skills move to the layout user-scope skills already use:

- Body at `.agents/skills/<name>/`; `.claude/skills/<name>` becomes a relative symlink to `../../.agents/skills/<name>`.
- Applies to `update-manual`, `update-readme`, `classify-tool-updates`, and the new `sync-agent-config`. Generator-owned `openspec-*` skills are excluded — `openspec update` has no target selection and regenerates per-tool copies.
- `.opencode/skills` needs no entry: OpenCode discovers `.agents/skills` and `.claude/skills` natively.
- Junie's `.agents/skills` support is contested — its docs claim it, [JUNIE-2381](https://youtrack.jetbrains.com/projects/JUNIE/issues/JUNIE-2381) is still open — so `.junie/skills/<name>` gets a symlink, subject to a discovery check.
- Stale `.codex/skills` (generated by openspec 1.7.0, superseded by `.agents/skills`) is left alone: generator-owned.

## Capabilities

### New Capabilities

- `sync-agent-config-skill`: skill that proposes cross-tool replication of user-scope agentic-tool config across Claude Code, OpenCode, and Junie, and maintains the parity table.
- `repo-skill-canonical-layout`: repo-owned skills live once under `.agents/skills/` and are exposed to each tool by symlink, with the per-tool discovery rules that make that safe.

### Modified Capabilities

- `update-manual-skill`: the requirement fixing the skill at `.claude/skills/update-manual/SKILL.md` changes to the canonical body plus symlink layout.
- `update-readme-skill`: same path requirement change for `update-readme`.
- `classify-tool-updates-skill`: same path requirement change for `classify-tool-updates`.

## Impact

- **New**: `.agents/skills/sync-agent-config/{SKILL.md,parity.md}`.
- **Moved**: `.agents/skills/{update-manual,update-readme,classify-tool-updates}/` become the bodies; the `.claude/skills/` entries become symlinks; the duplicated `.junie/skills/` copies are replaced by symlinks.
- **Untouched**: everything under `dot_claude/` and `dot_config/opencode/` (the skill only proposes), all `openspec-*` skill copies, `.codex/skills`, and `.claude/commands/`.
- **Not deployed by chezmoi**: repo-root dot-directories are ignored by chezmoi, so none of this reaches `$HOME`.
- **Verification required, not assumed**: whether OpenCode and Junie double-load a skill reachable both as `.agents/skills/<name>` and through a symlink, and whether Junie discovers `.agents/skills` at all.

## Corrections to the main dossier

**1. Operational step 5 (`:149`) and open question 6 (`:199`) — dolt.** Rewrite step 5 as a footnote; close #6 as answered. The current text's either/or ("either declare `dolt` explicitly in `BREW_PACKAGES` or drop the pinning advice") is wrong on both branches: declaring it is inert (see gap 6 above), and the pinning advice does not need dropping so much as demoting. Grounds:
- Homebrew never installs intermediate versions — `brew info dolt` reports stable 2.2.3, cache fresh, dolt unpinned; 2.1.10 → 2.2.3 in one hop. An intermediate could only arrive via a stale API cache under `HOMEBREW_NO_AUTO_UPDATE=1` (unset anywhere in this repo), a deliberate `brew extract`, or a non-brew dolt on PATH.
- The #11317 panic's precondition is a **VIRTUAL** generated column. Every beads 1.1.2 generated column is `STORED` (`internal/storage/schema/cli_migrations.go:90`, `migrations/0041_split_dependencies_target.up.sql:96`, `migrations/0047_recompute_mixed_is_blocked.up.sql:109`), and the steady-state schema drops them (`0043_drop_dependencies_generated_column.up.sql`, `migrations/ignored/0005_…`). Zero VIRTUAL declarations in the beads tree.
- Keep the free `brew info dolt` = 2.2.3 pre-flight; it is the only enforcement available. Keep the 2.2.2 `dolt gc` live-journal bug (#11312) as the *second* reason for the pre-flight — it is version-gated regardless of column type, and dropping step 5 wholesale would lose it. The repo's existing idiom for this is the upgrade task line (cf. `openspec/changes/archive/2026-05-02-bump-brew-deps/tasks.md:8`), not `BREW_PACKAGES`.

**2. `:179` and `:208` — the dolt format citation is under-specified.** `go/store/types/format.go` contains no version string; it defines `Format_DOLT` and delegates `VersionString()` to `constants.FormatDoltString`.
